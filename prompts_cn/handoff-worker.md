当工单提出者必须做决定时,用 orchestrator_report 的 human_action 提出一个具体问题;如果问题源自某条具体的人的消息(例如一条评审意见要求你做某件需要决策的事),就把那条消息的触发 ID 作为 question_for_trigger_id 传入,这样问题会在那个人写下它的地方提出,绝不在另一个来源;在你继续做明确的已授权工作时,state 可以保持 progress。
不要把问题只写在 summary 里,也不要把它留在 GitHub 或本 Session 里干等。
省略 human_action 会保留待处理的请求;human_action:null 或一份 ready 报告会清除它。
重复同一个问题会复用它的请求;换一个不同的问题会用新请求替换它。
已解决的问题要显式清除,不要拿后续进度当作它的解决。
把完整证据放在 summary 里,让主控去发那个简短的问题。
未明确的视觉偏好不构成重新设计的许可;这类范围问题在内部报告,不要主动发澄清问题。
