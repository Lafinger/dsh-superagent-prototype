# 工时接口文档（v3.1）

> 适用实例：`dsh-superagent-metahuman`（端口 3084）
> 只提供 JSON；CSV / Markdown 请求方式已移除。

## 1. 基础信息

| 项 | 值 |
|---|---|
| Base URL | 本机 `http://127.0.0.1:3084/orchestrator/api`；局域网 `http://192.168.2.170:3084/orchestrator/api` |
| 鉴权 | 无 Token，但必须带两个头（见下）|
| 访问范围 | **已放开局域网**（端口 `0.0.0.0:3084`）；可信 Host 白名单：`192.168.2.170:3084`、`10.242.14.211:3084` |
| 项目标识 / 名称 | 部署环境变量 `PROJECT_ID` 与 `PROJECT_NAME`（`docker/.env.metahuman`）；**各自留空时回退为 `GITHUB_REPOSITORY`**。改完 `up -d` 即生效，不需要重建镜像 |

### 必带请求头

```
Host: 127.0.0.1:3084
x-orchestrator-request: 1
```

> 缺任一头返回 `403 {"error":"Same-origin management request required"}`。

## 2. 接口一：查询工时

```
GET /orchestrator/api/timesheet?plan=<计划号>   # plan 可省略
```

| 参数 | 必填 | 说明 |
|---|---|---|
| `plan` | 否 | 计划 issue 编号；**省略时返回全部计划** |

### 响应（v2，仅 JSON）

```json
{
  "schema_version": 2,
  "project": {
    "id": "lafinger-agent/dsh-metahuman-demo",
    "name": "数字人 POC"
  },
  "plans": [
    {
      "number": 6,
      "url": "https://github.com/lafinger-agent/dsh-metahuman-demo/issues/6",
      "title": "计划：数字人 POC 知识库功能 v1.0",
      "content": "…（计划正文，只出现一次）",
      "roles": [
        {
          "key": "design",
          "name": "设计岗（产品）",
          "person": "陈小二",
          "tasks": [
            {
              "number": 7,
              "url": "https://github.com/lafinger-agent/dsh-metahuman-demo/issues/7",
              "title": "任务：设计岗 — 知识库功能产品说明",
              "content": "…（任务正文）",
              "pull": {
                "number": 4,
                "url": "https://github.com/lafinger-agent/dsh-metahuman-demo/pull/4",

              },
              "timestamps": {

                "plan_published": "2026-11-19T09:54:50Z",

              },
              "durations": {
                "planning": 0.35,
                "response": 0.45,
                "closing": 15.7,
                "total": 16.5
              },
              "missing": []
            }
          ]
        },
        {
          "key": "approver",
          "name": "管理岗",
          "person": "陈锦鸿",
          "tasks": [],
          "coordination": {
            "timestamps": {
              "requirement_start": "2026-11-19T09:33:49.101Z",
              "plan_published": "2026-11-19T09:54:50Z",
              "plan_completed": "2026-11-20T02:04:00Z"
            },
            "durations": {
              "confirm": 0.35,
              "close": 16.15
            }
          }
        }
      ]
    }
  ]
}
```

### 字段说明

| 字段 | 类型 | 说明 |
|---|---|---|
| `schema_version` | number | 固定 `2` |
| `project.id` / `project.name` | string | 仓库全名与项目名 |
| `plans[]` | array | 每个计划一个元素；带 `plan` 时只有一个 |
| `plans[].number/url/title/content` | number/string | 计划 issue，正文只出现一次 |
| `plans[].roles[]` | array | 岗位列表，含 `key` / `name` / `person` |
| `roles[].tasks[]` | array | 该角色的任务；管理岗为空数组 |
| `tasks[].number/url/title/content` | number/string | 任务 issue |
| `tasks[].pull` | object? | 结果 PR（`number/url/title/content`）；**无 PR 时整个字段缺失** |
| `tasks[].timestamps` | object | `requirement_start` / `plan_published` / `submitted` / `plan_completed`；缺失的时刻不出现 |
| `tasks[].durations` | object | `planning` / `response` / `closing` / `total`（小时）；无法计算时不出现 |
| `tasks[].missing` | string[] | 缺失时刻的语义名 |
| `roles[].coordination` | object? | **仅管理岗**：三个 `timestamps` + `durations.confirm/close`；**无 events** |

### 管理岗（`key: "approver"`）

- 来自 `settings/team.yml` 的 `approver` 块；`tasks` 恒为空数组；
- 只统计：需求开始、计划发布、计划完成，以及两段等待（`confirm` = 发布−开始，`close` = 完成−发布）；
- 不提交 PR、不合并 PR，也**不返回审阅事件**（审计留在飞书与工单里）；
- 团队文件没有 `approver` 时，该节点不出现。

## 3. 接口二：把工时表贴到计划 issue

```
POST /orchestrator/api/timesheet/post?plan=<计划号>
```

| 参数 | 必填 | 说明 |
|---|---|---|
| `plan` | 是 | 计划 issue 编号 |

### 响应

```json
{ "posted": true, "plan": 1, "rows": 2 }
```

- `posted=false`：该计划已有同款评论（带 `<!-- dsh-timesheet -->` 标记），不会重复发。
- 评论内容是 Markdown 表格，只在该接口内部生成；标题为 `## 工时（交付时长）：<项目名称> · <计划标题>`，项目名称未配置时省略前缀。

## 4. 错误码

| 状态码 | 场景 | 响应示例 |
|---|---|---|
| 400 | `plan` 传了但不是正整数 | `{"error":"plan must be a positive integer"}` |
| 400 | setup 未完成 | `{"error":"Setup is incomplete"}` |
| 403 | 缺少鉴权头 / Host 不匹配 | `{"error":"Same-origin management request required"}` |
| 404 | 计划号不存在 | `{"error":"Plan #99 not found"}` |

## 5. 调用示例

### PowerShell

```powershell
$h = @{ 'x-orchestrator-request' = '1' }
Invoke-RestMethod -Uri 'http://127.0.0.1:3084/orchestrator/api/timesheet?plan=1' -Headers $h |
  Select-Object -ExpandProperty rows |
  Format-Table task, role, person, response, closing, total
```

### curl（Windows / Linux）

```bash
curl -s -H "x-orchestrator-request: 1" \
  "http://127.0.0.1:3084/orchestrator/api/timesheet?plan=1"
```

### 容器内调用

```powershell
docker exec dsh-superagent-metahuman-dsh-superagent-1 sh -c `
  'curl -s -H "Host: 127.0.0.1:3084" -H "x-orchestrator-request: 1" `
  "http://127.0.0.1:3084/orchestrator/api/timesheet?plan=1"'
```

## 6. 局域网访问

**当前已放开**：

| 项 | 值 |
|---|---|
| 端口绑定 | `0.0.0.0:3084` |
| 可信 Host 白名单 | `192.168.2.170:3084`、`10.242.14.211:3084` |
| 调用地址 | `http://192.168.2.170:3084/orchestrator/api/timesheet?plan=1` |
| 请求头 | `Host: 192.168.2.170:3084` + `x-orchestrator-request: 1` |

不在白名单里的 Host 一律 `403 {"error":"Same-origin management request required"}`。

**要收回局域网访问**：

1. `docker-compose.metahuman.yml` 的 ports 改回 `"127.0.0.1:3084:3084"`；
2. 删掉环境变量 `DSH_ORCHESTRATOR_TRUSTED_HOSTS`；
3. 重建并重启容器。

> ⚠️ 写接口 `POST /timesheet/post` 与读接口在同一白名单下暴露，测试完记得收回。

## 7. 注意事项

- 所有时间都是 UTC 的 ISO 8601 字符串，展示时自行转 `Asia/Shanghai`。
- 时长单位是**小时**，浮点（`16.69` 表示 16 小时 41 分）。
- 接口每次**现算**，不读缓存；数据来自 SQLite（消息时间）与 GitHub（issue/PR 时间）。
- 一条记录正文合计约 4–5 KB，多任务计划注意响应体积。
