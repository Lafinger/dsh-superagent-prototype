# 项目创建接口（局域网）

| 项 | 值 |
|---|---|
| 服务 | 项目控制面网关（`docker/gateway`）|
| Base URL | `http://<宿主机IP>:3090` |
| 鉴权 | 无（仅限内网使用）|
| 页面 | 浏览器打开同一地址即可（新建 / 查看 / 删除）|

> ⚠️ 该接口能创建与删除 Docker 容器，**只能在受控内网开放**。当前只绑定 `192.168.2.170:3090`（`127.0.0.1` 不通），换机器时改 `GATEWAY_BIND`。

## 1. 端点总览

| 方法 | 路径 | 作用 |
|---|---|---|
| POST | `/projects` | 新建项目（建仓库 → 写 team.yml → 建容器 → 配群/准入 → 邀请协作者）|
| GET | `/projects` | 清单 + 容器状态 |
| GET | `/projects/{id}/status` | 单个项目状态 |
| DELETE | `/projects/{id}` | 删容器（保留数据卷与仓库）|
| POST | `/projects/{id}/reconcile` | 对齐已有项目的配置（不动容器）|
| POST | `/feishu/members` | 读飞书群成员（拿 open_id）|
| POST | `/repos/collaborators` | 单独维护仓库协作者 |

## 2. 新建项目

```
POST /projects
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `name` | ✅ | 项目标识（小写字母/数字/连字符），决定容器名与目录 |
| `displayName` | | 显示名 |
| `owner` | | 仓库 owner，默认 `lafinger-agent` |
| `repoName` | | 仓库名，默认 `dsh-<name>`；已存在则复用 |
| `collaborators` | ✅ | GitHub 登录名数组：**协作者 + 准入**（前两个还会写进默认两个岗位）|
| `appId` / `appSecret` | ✅ | 飞书应用凭据（**每个项目独立应用**）|
| `chatId` | | 飞书项目群 ID；填了就写入接收群 |
| `listen` | | `mentions`（默认）/ `all` |
| `feishuAllowed` | | 飞书准入 open_id；不填则自动用 `team` 里各人的 openId |
| `team` | | 岗位定义，见下：`approver{name,person,openId,github}` + `roles[]{key,name,person,order,openId,github,deliverableDir}` |

```json
{
  "name": "kb2",
  "displayName": "知识库项目",
  "collaborators": ["Lafinger", "zhengze736"],
  "appId": "cli_xxxxxxxx",
  "appSecret": "xxxxxxxx",
  "chatId": "oc_xxxxxxxx",
  "team": {
    "approver": { "name": "管理岗", "person": "陈锦鸿", "openId": "ou_xxx", "github": "Lafinger" },
    "roles": [
      { "key": "design",    "name": "设计岗", "person": "陈小二", "order": 1, "openId": "ou_yyy", "github": "Lafinger",   "deliverableDir": "design/" },
      { "key": "implement", "name": "实施岗", "person": "任泽义", "order": 2, "openId": "ou_zzz", "github": "zhengze736", "deliverableDir": "app/" }
    ]
  }
}
```

> `name` 是**岗位名**：审批人固定为「管理岗」（接口可传，省略即默认）；`person` 是**成员姓名**，写入 `team.yml` 的 `feishu_name`；`openId` 来自 `POST /feishu/members`。
> 面板只填成员与 GitHub，不再单独填岗位名。

响应（`201`，最长阻塞 5 分钟等容器 healthy）：

```json
{
  "id": "kb2", "port": 3085, "state": "healthy",
  "repo": { "full": "lafinger-agent/dsh-kb2", "created": true },
  "team": { "present": true, "status": 200, "roles": 2 },
  "settings": { "feishu": { "saved": true }, "github": { "saved": true }, "policy": { "saved": true } },
  "collaborators": [ { "login": "Lafinger", "ok": true, "existed": false } ]
}
```

`settings.*` 里出现 `error` 表示该项没写成功（其余照常）。

## 3. 查看 / 删除

```
GET    /projects             → [{ id, name, port, status: { running, health, image } }]
GET    /projects/{id}/status → { running, health, startedAt, image }
DELETE /projects/{id}        → { id, removed: true, volumesKept: true }
```

删除只移除容器，**数据卷与仓库都保留**。

## 4. 对齐已有项目

```
POST /projects/{id}/reconcile
```

```json
{ "chatId": "oc_…", "collaborators": ["Lafinger"], "team": { … }, "writeTeam": false, "replace": false }
```

- 只处理传了的字段；**只写有变化的配置块**，返回 `changed[]`（空数组表示无需变更）；
- `writeTeam: true` 才覆盖仓库里的 `team.yml`（默认只校验）；
- `replace: true` 才整体替换准入名单（默认只增不减）；
- 不动容器、不动数据卷、不动工单历史。

## 5. 读群成员（拿 open_id）

```
POST /feishu/members
{ "appId": "cli_xxx", "appSecret": "xxx", "chatId": "oc_xxxxxxxx" }
→ { "members": [ { "openId": "ou_xxx", "name": "陈小二" } ] }
```

## 6. 维护协作者

```
POST /repos/collaborators
{ "repository": "lafinger-agent/web-test", "logins": ["Lafinger", "zhengze736"], "permission": "push" }
```

幂等；需要 token 对该仓库有 admin 权限。

## 7. 错误码

| 状态 | 场景 |
|---|---|
| `400` | 项目名非法、缺飞书凭据、`collaborators` 为空、岗位 key 重复 |
| `404` | 项目不存在 |
| `409` | 项目名已存在、端口被占用 |
| `500` | Docker / GitHub 返回错误（响应体带原因）|

## 8. 创建后请确认

1. 协作者收到**邀请**，对方接受后才能推 PR；
2. 机器人已加入项目群（否则收不到消息）；
3. 仓库里 `settings/team.yml` 已生成（`team.present: true`）；
4. 飞书与 GitHub 准入名单各有至少一人。
