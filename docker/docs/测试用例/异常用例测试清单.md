## E1 成果阶段异议（ADR 0007）— 旗舰
**场景**：产品先交付成果，前端验收时提出异议 → 不推进/不合并 → 退回产品返工 ≤2 轮 → 仍不达成则升级审批人 → 审批人裁决（接受/改稿/终止）并回帖。

**用轻量方式**（成果用飞书提交，避开 PR 摩擦；如需验"不合并"可改用 PR 版）：
1. 发需求（新案例名，例如「极简倒计时（单页应用）V1」）：
```
【需求：极简倒计时（单页应用）V1】
背景：做个自己用的极简倒计时网页。
功能：1 设置分钟数开始倒计时；2 开始/暂停/重置；3 结束提示；4 本地保存上次设置。
非功能：单页 index.html，无登录/后端；375/1280 适配。
交付：产品一份产品方案；前端 index.html + 桌面/手机截图 + README。
验收：能设置并倒计时、暂停/重置可用、结束有提示、375/1280 正常。
```
2. 产品、前端各回「同意」→ 机器人应建 **plan + 2 个 task**，贴链接。
3. 产品（Lafinger）在话题里**提交产品成果**（可用一段方案要点，或 PR 链接），并 @前端验收。
4. 前端（陈小二）回异议：
```
异议：方案缺少"倒计时结束"的提示形式与声音/静音规则，请补充后再交付。
```
**预期**：机器人**不推进到前端实现、不合并**，把异议退回产品返工，重新请前端验收；此类返工 **≤2 轮**。
5. 产品补一版后再交付，前端**再异议一次**（第 2 轮）→ 机器人应**升级审批人**（接受/改稿/终止三选一）。
6. 审批人（Lafinger）裁决，例如「终止该计划」。
**核验点**：① 全程未建前端实现/未合并；② 返工计数 ≤2；③ 第 3 次不达成即升级；④ 审批人裁决后**线程出现机器人回帖**（接受则继续、终止则"已按人工指示终止…"）。

## E2 含糊需求（H7）
**话术**（@项目助手）：
```
【需求：个人小工具】帮我做一个好看又实用的小工具，功能你看着办，尽快给我。
```
**预期**：机器人指出**需求含糊、缺验收标准/范围**，列出开放问题（用途？平台？核心功能？验收标准？），**请对方补充；不建计划、不进入确认**。
**核验**：无新 plan issue；线程有清晰问题清单；机器人不臆造功能。

## E3 非角色发言（H9）
**前置**：任一"计划草案待确认"的工单在等确认（可配合 E1 第 1~2 步）。
**话术**：让一个**不在 team.yml 名单里**的账号（需第三个群成员）在草案下回：
```
同意
```
**预期**：机器人**忽略该答复**，并说明"只有 team.yml 中的角色/审批人的答复才算；请名单内角色确认"。
**核验**：机器人不因该"同意"而建计划；线程明确点名"谁的答复才算"。
> 若暂无名单外账号，可跳过或用临时加入的测试账号。

## E5 进度/问题询问（M5）
**前置**：任一活动工单进行中。
**话术**：
```
现在进展到哪一步了？
```
**预期**：机器人**只读汇报**（读工单与 issues），**不改计划、不跑外部动作、不当作同意/授权**。
**核验**：工单状态、plan 无变化；回复内容为只读进展。

---

## E6 完成关闭（H6）
**场景**：走完一个正常流程到完成。
**步骤**：新案例 → 双方同意 → 建 plan+2 task → 产品交付并被接受 → 前端交付并被接受/合并 → 机器人宣布完成。
**预期**：帖子宣布结果、**只关闭它自己创建的 plan 与 2 个 task issue**、不动其他 issue、`report ready` 并回帖。
**核验**：被关的 issue 集合 = 它创建的那些；无越权关闭；线程有完成回帖。

## E7 团队变更（H10，可选）
**前置**：我在 team.yml 改某角色的 feishu_open_id/名字，或删掉某人。
**预期**：机器人**以当前文件为准**；若必需的人不在了，请补人并等待，不瞎猜。
**核验**：机器人引用最新 team.yml；缺失时提示补充而非硬推进。
