# 产品方案：个人待办清单（Todo）单页应用

> 依据：`materials/requirements/客户需求文档-Todo单页应用.md`
> 关联：计划 #4 / 任务 #5
> 版本：v1（2026-11-05）

## 1. 背景与目标

客户希望有一个可在浏览器直接打开、无需注册登录、数据保存在本机的个人待办清单单页应用，用于快速记录待办、标记完成、随时查看剩余未完成事项。本方案是其第一步：给出页面结构、主要交互流程、关键文案与响应式布局要点，作为前端实现的直接依据。

目标：

- 一页完成「记、看、勾、改、删」全部核心操作。
- 移动端与桌面端均可正常使用。
- 界面简洁清爽、阅读舒适，文案使用简体中文。

## 2. 范围

### 2.1 本期范围

- 新增待办（输入一句话即可添加）。
- 完成 / 取消完成。
- 编辑已添加待办的文字。
- 删除单条待办。
- 「全部 / 未完成 / 已完成」三种筛选切换，并显示未完成数量。
- 本地持久化：刷新或重开浏览器后数据仍在。
- 空状态提示。
- 响应式布局（移动端 / 桌面端）。

### 2.2 非目标（本期不做）

- 账号体系、注册登录。
- 云同步、多人协作。
- 消息提醒。
- 后端服务。
- 排序拖拽、截止日期、优先级、标签等扩展字段（除非后续追加需求）。

## 3. 页面结构

### 3.1 整体布局（自上而下）

单页、单列、居中卡片式布局。从上到下依次为：

1. 顶部标题区：应用标题「我的待办」。
2. 新增输入区：文本输入框 + 「添加」按钮。
3. 筛选区：三个筛选标签（全部 / 未完成 / 已完成）+ 未完成数量提示。
4. 列表区：待办条目列表（每条含勾选框、文字、编辑入口、删除入口）。
5. 空状态区：当前视图无数据时显示对应提示（与列表区互斥）。

### 3.2 线框图（示意）

```
┌───────────────────────────────────────────────┐
│  我的待办                                       │
│ ┌───────────────────────────────┐  ┌────────┐  │
│ │ 添加一条待办，回车即可保存       │  │  添加  │  │
│ └───────────────────────────────┘  └────────┘  │
│                                                │
│  全部        未完成 (3)        已完成           │
│ ─────────────────────────────────────────────  │
│  ☐  买牛奶                            ✎    🗑   │
│  ☑  ~~写周报~~                        ✎    🗑   │
│  ☐  给妈妈打电话                       ✎    🗑   │
│                                                │
│  还剩 2 项未完成                                │
└───────────────────────────────────────────────┘
```

（`☐ / ☑` 为勾选框；`✎` 为编辑入口；`🗑` 为删除入口。移动端将输入框与「添加」按钮改为上下整行堆叠。）

### 3.3 区域说明

- **标题区**：仅展示标题，不参与交互。
- **新增输入区**：输入框占满可用宽度；桌面端与「添加」按钮同行居中，移动端整行堆叠；按钮触控区域 ≥44px。
- **筛选区**：三个标签横向排列（可等分），当前选中项高亮；「未完成」标签后显示未完成数量（如 `未完成 (3)`）。数量为 0 时显示 `未完成 (0)`，并展示统计文案 `全部完成`。
- **列表区**：每条待办由「勾选框 + 文字 + 编辑入口 + 删除入口」组成；已完成条目文字加删除线并弱化颜色。
- **空状态区**：当前筛选视图无任何条目时替换列表区显示，文案随筛选不同而不同（见第 5 节）。

## 4. 主要交互流程

### 4.1 新增

1. 光标聚焦输入框，输入待办文字。
2. 按 `Enter` 或点击「添加」。
3. 校验：去除首尾空白后为空则不新增，输入框保持焦点；非空则新增成功。
4. 新条目插入列表**顶部**（最新在最上），输入框清空并保持聚焦，便于连续录入。
5. 若当前处于「已完成」筛选下新增，则新条目（未完成）不在该视图显示，但仍写入数据并更新未完成数量。

### 4.2 完成 / 取消完成

1. 点击条目左侧勾选框。
2. 勾选：`done = true`，文字加删除线并弱化；取消勾选：`done = false`，恢复正常样式。
3. 已完成项**保持原位置**，不自动移到底部。
4. 更新未完成数量；若当前筛选下该条目不再满足条件，则从当前视图移除（如「未完成」视图中勾选后消失）。

### 4.3 编辑

1. 双击待办文字（移动端着重点击 `✎` 图标）进入**行内编辑**，文本框内为原文并聚焦、全选。
2. `Enter` 或失焦保存；`Esc` 取消并还原原文。
3. 校验保存内容：去除首尾空白后为空则**删除该条**（视为删除，避免出现空待办）；非空则更新文字。
4. 编辑不改变条目创建时间与排序位置。

### 4.4 删除

1. 点击条目右侧 `🗑` 删除入口。
2. 点击即删，**不弹二次确认、不提供撤销**（保持最简）。
3. 删除后从列表移除并更新未完成数量；删除入口采用红色悬停作危险提示。
4. 若删除后当前视图为空，则显示对应空状态。

### 4.5 筛选切换

1. 点击「全部 / 未完成 / 已完成」任一标签。
2. 列表即时按条件过滤：全部=所有条目；未完成=`done=false`；已完成=`done=true`。
3. 当前标签高亮；切换只改变视图，不改变数据。
4. 视图为空时展示对应空状态文案。

### 4.6 空状态

- 全部视图为空 → `还没有待办，添加第一条吧`
- 未完成视图为空 → `太棒了，没有未完成的待办`
- 已完成视图为空 → `还没有已完成的待办`
- 空状态居中展示，可配简单图标（可选）。

### 4.7 刷新 / 持久化

1. 任意增删改操作后立即写回 localStorage。
2. 页面加载时读取 localStorage 并渲染。
3. 读取失败（非法 JSON 等）时清空并从头开始，保证页面不报错。

## 6. 移动端与桌面端布局要点

- 统一单列、居中卡片，最大宽度约 640px，两侧留安全边距。
- 断点约 640px：
  - **桌面（≥640px）**：输入框与「添加」按钮同一行、居中；筛选标签横向排列；列表左右对齐。
  - **移动端（<640px）**：输入框与「添加」按钮**整行堆叠**（输入框在上、按钮占满宽度或紧随其下）；筛选三等分展开；条目左右留白收窄。
- 触控：所有可点击区域（勾选框、编辑、删除、筛选）点击区 ≥44×44px。
- 字体：正文字号 ≥16px，避免 iOS 聚焦时自动缩放。
- 长文本：待办文字过长时自动换行，不撑破卡片；两行截断可选。
- 视觉：浅色主题、白底卡片、圆角 + 轻阴影、主色蓝（`#2F6FEB`）、系统字体；已完成文字加删除线并弱化颜色。

## 7. 数据与持久化

- 存储位置：浏览器 `localStorage`。
- 键名：`todo-app:v1`。
- 值：JSON 数组，元素结构：

  ```json
  { "id": "string", "text": "string", "done": false, "createdAt": 1699000000000 }
  ```

  - `id`：唯一标识（可用时间戳 + 随机数生成）。
  - `text`：待办文字。
  - `done`：是否完成。
  - `createdAt`：创建时间戳（毫秒），用于**倒序**渲染。
- 读写时机：启动读取并渲染；每次新增 / 编辑 / 删除 / 勾选后立即写回。
- 容错：`JSON.parse` 失败或结构非法时，按空列表处理并重置存储，控制台不抛错。

## 9. 术语表

- **待办 / Todo**：一条被记录的待办事项，含文字与完成状态。
- **完成 / 未完成**：待办的完成状态，对应 `done=true` / `done=false`。
- **未完成数量**：当前所有未完成待办的条数，用于统计与展示。
- **筛选 / 视图**：全部 / 未完成 / 已完成三种查看方式，仅改变展示、不改变数据。
- **空状态**：当前筛选视图下没有任何待办时展示的提示。
- **持久化**：把数据保存在浏览器本地（localStorage），刷新或重开仍存在。
