## 2. 创建项目

```
POST /projects
```

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `name` | string | 是 | 项目标识：小写字母、数字、连字符，唯一。决定容器名 `dsh-superagent-<name>-dsh-superagent-1`、目录、网络别名 |
| `displayName` | string | 否 | 显示名，默认同 `name` |
| `repository` | string | 否 | `owner/repo`；省略时自动用 `owner` + `repoName` 拼出 |
| `owner` | string | 否 | 仓库 owner，默认 `lafinger-agent` |
| `repoName` | string | 否 | 仓库名，默认 `dsh-<项目名>` |
| `createRepo` | boolean | 否 | 默认 `true`：仓库不存在就建（私有 + 初始化 README）|
| `approverOpenId` | string | 否 | 写进自动生成的 `team.yml`，作为管理岗的 open_id。**面板已不再单独填岗位名**，审批人固定为「管理岗」|
| `team` | object | 否 | 自定义岗位：`{ approver: {name,openId,github}, roles: [{key,name,order,openId,github,deliverableDir}] }`；省略时默认 `design`(order 1) + `implement`(order 2)，github 取 collaborators |
| `port` | integer | 否 | 实例端口；省略时从 3085 起自动分配 |
| `appId` / `appSecret` | string | 是 | 飞书应用凭据（**每个项目一个独立应用**）|
| `chatId` | string | 否 | 飞书项目群 ID（`oc_` 开头）；填了就写入接收群 |
| `listen` | string | 否 | `mentions`（仅 @，默认）/ `all` |
| `feishuAllowed` | string[] | 否 | 准入的飞书用户 open_id 列表；不填则**没人能发起工作** |

| `directMessages` | boolean | 否 | 是否接收私聊，默认实例默认值 |
| `otherChats` | string | 否 | `none`（默认）/ `mentions`：未列出的群是否接收 @ |
| `observe` | object | 否 | GitHub 观察开关：`{issues,pulls,comments,ci}` |
| `image` | string | 否 | 镜像标签，默认复用 `GATEWAY_DEFAULT_IMAGE`，**不构建** |
| `ghUser` | string | 否 | GitHub 账号，默认取 `defaults.env` |
| `collaborators` | string[] | **是** | GitHub 登录名（至少一个）。**一份名单两用**：加为仓库协作者（push）+ 写进准入名单（谁能在 Issue 里提需求）；前两个还会分别写进 `team.yml` 的两个默认岗位 |
| `collaboratorPermission` | string | 否 | 协作者权限，默认 `push`（可 `pull` / `maintain` / `admin`）|

**请求示例**

```json
{
  "name": "kb2",
  "displayName": "知识库项目",
  "repository": "lafinger-agent/kb2-demo",
  "port": 3085,
  "appId": "cli_xxxxxxxx",
  "appSecret": "xxxxxxxx",
  "chatId": "oc_xxxxxxxx",
  "listen": "mentions",
  "feishuAllowed": ["ou_xxxxxxxx"],
  "collaborators": ["Lafinger", "zhengze736"]
}
```

**成功响应 `201`**（阻塞到容器 healthy，最长 5 分钟）

```json
{
  "id": "kb2",
  "port": 3085,
  "image": "dsh-collaborationagent:8fb0922…",
  "state": "healthy",
  "settings": {
    "feishu": { "saved": true, "revision": 2, "restarting": true },
    "github": { "saved": true, "revision": 1, "restarting": true },
    "policy": { "saved": true, "revision": 1, "policy_changed": true }
  },
  "repo": { "full": "lafinger-agent/dsh-kb2", "created": true },
  "team": { "present": true, "status": 200, "roles": 3 },
  "team": { "present": true, "status": 200 },
  "collaborators": [
    { "login": "Lafinger", "ok": true, "permission": "push" },
    { "login": "zhengze736", "ok": true, "permission": "push" }
  ]
}
```

`settings.*` 里若出现 `error`，表示该项没写成功（例如仓库不可读）；其余项仍会继续执行。

服务端动作：写 `docker/dsh-superagent-<name>/{docker-compose.yml,.env}` → 建 4 个数据卷 → 建容器（加入 `dsh-shared`，别名 `<name>`）→ 启动 → 等 healthy → 写实例设置 → 检查 `team.yml` → 登记 `gateway/projects.json`。

## 2.2 读取群成员（填 open_id 用）

```
POST /feishu/members
{ "appId": "cli_xxx", "appSecret": "xxx", "chatId": "oc_xxxxxxxx" }
```

```json
{ "members": [ { "openId": "ou_xxx", "name": "陈小二" }, { "openId": "ou_yyy", "name": "陈锦鸿" } ] }
```

网关用应用凭据取 `tenant_access_token` 再调飞书 `im/v1/chats/{chatId}/members`，**不需要 lark-cli**；失败时返回 400 与原因，可回退手工填 open_id。

## 4. 单个项目状态

```
GET /projects/{id}/status
```

容器不存在时返回 `running: false` 并带 `error`。

### 2.1 team.yml 生成规则

```json
"team": {
  "approver": { "name": "管理岗", "person": "陈锦鸿", "openId": "ou_xxx", "github": "Lafinger" },
  "roles": [
    { "key": "design",    "name": "设计岗（产品+UI）", "order": 1, "github": "Lafinger",   "deliverableDir": "design/" },
    { "key": "ui",        "name": "UI 细化",            "order": 2, "github": "Lafinger",   "deliverableDir": "design/ui/" },
    { "key": "implement", "name": "实施岗（全栈）",      "order": 3, "github": "zhengze736", "deliverableDir": "app/" }
  ]
}
```

- `key` 必填且唯一，`order` 决定交付顺序；`openId` 来自 `POST /feishu/members`（也能手填）；`person` 是成员姓名，写进 `team.yml` 的 `feishu_name`；`approver.name` 省略时固定为「管理岗」；
- 省略 `github` 时按 collaborators 顺序回填；
- 省略整个 `team` 时用默认两岗位。

## 4.1 单独维护仓库协作者

```
POST /repos/collaborators
```

```json
{ "repository": "lafinger-agent/dsh-metahuman-demo", "logins": ["Lafinger", "zhengze736"], "permission": "push" }
```

幂等：已是协作者也返回成功。需要 `GH_TOKEN` 对该仓库有 **admin** 权限。

## 4.2 对齐已有项目的配置（reconcile）

```
POST /projects/{id}/reconcile
```

```json
{
  "chatId": "oc_xxxxxxxx", "listen": "mentions",
  "team": { "approver": {…}, "roles": [{ "key": "design", "name": "设计岗", "order": 1, "openId": "ou_…", "github": "Lafinger", "deliverableDir": "design/" }] },
  "collaborators": ["Lafinger", "zhengze736"],
  "writeTeam": false,
  "replace": false
}
```

| 字段 | 默认 | 说明 |
|---|---|---|
| `writeTeam` | `false` | 是否用传入的 `team` **覆盖**仓库里的 `team.yml`；默认只校验不覆盖 |
| `replace` | `false` | 准入名单是否**整体替换**；默认只增不减 |
| 其余 | — | 与创建接口同名含义；只处理传了的字段 |

行为：

1. 读实例设置 → 逐块算出"期望值"；
2. **只写有变化的块**（`feishu` / `github` / `policy`），没变化就跳过；
3. `writeTeam: true` 才写 `team.yml`；
4. 按 `collaborators` 幂等补协作者（`existed: true` 表示本来就在）；
5. 返回 `changed[]`，空数组表示无需变更。

**不动容器、不动数据卷、不动工单历史。**

```json
{ "id": "metahuman", "ok": true, "changed": [],
  "team": { "present": true, "status": 200, "written": false, "roles": null },
  "settings": { "feishu": {"saved":false,"changed":false}, "github": {"saved":false,"changed":false}, "policy": {"saved":false,"changed":false} },
  "collaborators": [ { "login": "Lafinger", "ok": true, "existed": true } ] }
```

> 注意：用 `replace: true` 且只传 open_id 字符串时，名单里的**姓名会被清空**；要保留姓名请传 `{"id":"ou_…","name":"陈锦鸿"}`。

## 5. 删除项目

```
DELETE /projects/{id}
```

```json
{ "id": "kb2", "removed": true, "volumesKept": true }
```

停并删容器，**保留 4 个数据卷**，并移出清单。

## 6. 错误码

| 状态 | 场景 |
|---|---|
| `400` | 项目名非法、`repository` 格式不对、缺飞书凭据、端口非法 |
| `404` | 项目不存在 |
| `409` | 项目名已存在、端口被占用 |
| `500` | Docker 返回错误（响应体带原因）|

错误响应统一 `{ "error": "说明" }`。

## 7. 新实例会被自动补齐的配置

以下项**不需要调用方填**，网关在容器启动后写入实例：

| 项 | 值 |
|---|---|
| 飞书来源 `cli` | `/root/.local/bin/lark-bot`（缺失时自动补，否则报 `agentCliUnset`）|
| GitHub 来源 `cli` | `/root/.local/bin/gh-agent`（同上）|
| GitHub 仓库 | 请求里的 `repository` |
| 接收群 | 请求里的 `chatId` + `listen`（幂等合并）|
| 准入名单 | 飞书：未传 `feishuAllowed` 时**自动取 approver + 各岗位的 openId**；GitHub 直接用 `collaborators`（与已有合并）|
| 模型与 GitHub token | 继承 `gateway/defaults.env` |
| 仓库 | 不存在就建私有库（`auto_init`），并写 `settings/team.yml`（approver + 面板配的任意数量岗位；省略 `team` 时默认 design/implement）|
| 仓库协作者 | 按面板填的 `collaborators` 逐个邀请为 `push` 协作者（未接受的显示为 pending invitation）|

## 8. 创建前请确认

1. **飞书应用是独立的**（不同实例共用会抢事件），且机器人已加入目标群；
2. **仓库存在且机器人账号可读**，否则 `settings.github` 会返回 `repositoryUnreadable`；
3. **仓库里有 `settings/team.yml`**（`approver` + `roles`），否则计划阶段无法分配岗位，响应里 `team.present` 为 `false`；
4. 准入名单至少各有一个（飞书 `feishuAllowed`、GitHub `collaborators`），否则对应来源的请求变不成功单；
5. 协作者是**邀请**形式，对方要在 GitHub 上接受后才能真正推 PR；
6. token 权限现为 `delete_repo, repo, workflow`：可建库、也可删库（删库属于危险操作，网关默认不自动删，需显式触发）。
