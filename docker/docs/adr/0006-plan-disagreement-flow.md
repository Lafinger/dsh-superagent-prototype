# 计划确认遇异议：改稿最多两轮 → 升级审批人 → 否则挂起

## Context
协调者（Project Worker）出计划草案后，需产品与前端分别确认。此前提示词只写了"全部同意才出正式计划"，**没有定义"有一方不同意"的后续**：既不建计划（安全正确），但会停在等待、行为不确定，只能人工介入。

## Decision
把异议流程写进 skill / 提示词：
1. 任何角色声明不同意 → **不算同意，绝不创建正式计划**；
2. 协调者在线程记录异议、**修订草案回应异议**，重新 @ 双方求同意，**最多两轮**；
3. 仍不同意 → **@ `settings/team.yml` 里的 approver** 陈述双方立场，请其裁决；
4. approver 说"调整"或"继续"就照办；说"停止"或迟迟无裁决 → 协调者把工单**标记 blocked**（带具体待决问题）并停下。
全程：未获确认绝不进入执行。

## Considered Options
- **一票否决直接挂起**（最简）：确定但每次都要人工。
- **无限改稿**：可能来回消耗，不可控。
- **改稿两轮 + 升级审批人 + 否则 blocked**（采用）：先自愈、再拍板、最后可预期地挂起。

## Consequences
- 否决永远不会误触发工作（保持既有安全不变式）。
- 异议有确定路径与止点：2 轮改稿上限、审批人拍板、否则 blocked。
- 依赖 `settings/team.yml` 的 `approver` 字段（现为 Lafinger）；缺失时按"无裁决 → blocked"处理。
- 工单不会被自动关闭；终止走"blocked 等人"，或由人 `stop`（结局 `stopped`）、协调者 `dropped`。
